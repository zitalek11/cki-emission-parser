# Агентские правила: парсер эмиссионных документов

Система извлекает факты из эмиссионных документов. Она не «заполняет таблицу НРД как считает правильным».

## Обязательно

- Нет доказательства → нет значения. Статус `not_found` допустим и предпочтительнее выдумки.
- Каждый принятый факт имеет `source_id`, страницу или якорь, цитату.
- Примеры и Excel — эталонный набор, не перечень допустимых эмитентов, типов бумаг и комплектов.
- Новый эмитент, новый выпуск, неизвестный раздел, неизвестный тип документа не являются сами по себе ошибкой пайплайна.
- Неизвестный параметр сохранять как `unmapped_fact`, не запихивать в «похожее» поле.
- LLM не повышает статус до `confirmed`. Это делает код после проверки цитаты.
- `derived` только если правило есть в коде (`derivation_rule`).
- Молчание документа не равно `false` / «нет».
- CFI не выводить из признаков бумаги.
- Краткое наименование не выводить из полного.
- Правило даты («N-й день с даты начала размещения») не сводить к календарной дате.
- План и факт размещения — разные поля.
- Конфликт документов → `conflict`, обе цитаты сохраняются.
- Внешние источники выключены, пока не включены явно. НРД, агрегаторы, Wikipedia — не источник факта.

## Запрещено

- Правила вида «если эмитент = МТС → …», «если документ похож на Пример_1 → …».
- Добавлять в промпт сотни примеров и частных формулировок вместо починки слоя.
- Считать систему готовой по доле заполненных полей. Главная метрика — `unsupported_value_rate` → 0.

## Слои

ingest → parse/OCR → classify → index → retrieve → extract(LLM) →
normalize(code) → validate(code) → verify(quote) → reconcile → score → JSON/Excel/HTML
